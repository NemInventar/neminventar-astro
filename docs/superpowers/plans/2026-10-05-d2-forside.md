# D2 · Den nye forside — implementeringsplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `src/pages/index.astro` bliver mockuppen `mockups/forside-v3.html`: tre veje i toppen, bevisbjælke, inspiration, "Det laver vi", proces, projekter, kulører og kontakt — bygget af v2's komponenter og data fra Supabase-views.

**Architecture:** Statisk Astro-side. Toppen er `HeroPaths.astro` med tre paneler; 3D'en er en isoleret klient-modul `src/scripts/hero3d.ts` (midlertidig, se nedenfor), sendepanelet en React-ø `SendPanel.tsx` omkring `ContactForm`/`CallbackForm`. Udvalg og rækkefølge står i `src/lib/forside.ts`; alt indhold kommer fra views.

**Tech Stack:** Astro 6, React 19 (øer), three@0.128 (dynamisk import, kun computer/ved tryk), site.css.

**Spec:** `docs/superpowers/specs/2026-10-05-ny-forside-design.md` §5-6. **Gren:** `forside-v3`.

**Afvigelse fra spec §6 (besluttet under implementeringen, skal godkendes af Joachim):** Indtil designer-sessionens `indlejr.v1.js` findes, bruger toppen mockuppens lette three.js-model (lockers + højskab) — **uden pris, uden IFC/DXF**. Den ligger i én fil (`src/scripts/hero3d.ts`) med samme API som kontrakten (`saet`, `on('aendret')`, `ryd`), så den kan skiftes ud uden at røre siden. Begrundelse: uden 3D er toppen statisk, og det var 3D'en, der bar mockuppen.
